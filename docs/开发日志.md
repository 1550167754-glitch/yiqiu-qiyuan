## 三、关键技术实现

### 3.1 渲染管线：4× 超采样抗锯齿 + 真 Alpha 合成

所有图形元素（棋盘、棋子、按钮、图标）统一走同一条管线：

```
SS=4 超采样绘制 → BOX 面积平均降采样 → UnsharpMask(1.1, 60, 2) 找回锐度 → 重建 Alpha
```

- **超采样**：在 4 倍分辨率空间绘制，天然获得抗锯齿边缘；
- **降采样**：使用 `Image.Resampling.BOX`（面积平均、无负瓣）——相比 LANCZOS 在高对比边界不产生彩色振铃；
- **真 Alpha**：降采样后重建 alpha mask（圆内恒 255 + 边缘羽化），避免"半透明发虚"观感；
- **运行时零重绘**：精灵预渲染 + Canvas 项坐标移动，配合 `after(7ms)` 调度（≈144Hz）保证动画顺滑。

### 3.2 音效系统：MCI 双队列 + 常驻别名

音效与背景音乐统一走 MCI（`winmm`），核心设计：

- **独立工作线程**：UI 主线程调用 `play()` 只入队立即返回，即使音频设备异常也绝不冻结界面；
- **常驻 alias**：首次播放时 `open` 设备并常驻，重播只需 `seek to start` + `play`，消除每次重开的设备初始化开销；
- **双队列分流**：MP3（`mpegvideo`，play 异步）与 WAV（`waveaudio`，play 同步阻塞）分属两条工作队列，WAV 的阻塞不再拖累落子音效；
- **自定义素材保护**：`_CUSTOM_FILES` 机制让用户提供的 `.mp3` 素材优先接管音效，且不被音量设置时的合成重写覆盖；
- **自愈机制**：全局锁被异常线程永久持有时，`force_unlock` + `recover()` 整体换锁，避免"音效与背景音双双永久静默"。

### 3.3 AI 引擎

- **自研 AlphaBeta**：面向 Connect6 / Gomoku 的搜索引擎，含增量评估、置换表、着法排序；
- **VCF/VCT 杀棋搜索**：五子棋三档难度（easy / medium / hard）的核心差异；连续冲四（VCF）与连续威胁（VCT）搜索带 deadline 控制，MIN 层只生成堵点，防守系数按行棋方动态取值；
- **象棋引擎**：接入本地 Pikafish（皮卡鱼）NNUE 神经网络引擎，UCI 子进程封装，三档 Skill/depth 预设，异步 loader 线程 + 队列轮询，失败明确弹窗回退，禁止静默降级。

### 3.4 数据与配置

- PostgreSQL 存档战绩与回放（`config/database.ini` 配置端口与密码）；
- 提供 `scripts/一键配置PostgreSQL.bat`（面向非技术用户，详见第五轮迭代）；
- 本地目录职责清晰：`assets/music`（背景音乐）、`data/战绩`、`data/回放`、`logs`（归档截图）。

### 3.5 打包与分发

- PyInstaller 冻结为 `dist\六子棋\六子棋.exe`；
- 日常开发与运行走 `启动六子棋.bat`（venv 直接跑源码），`dist` 仅用于分发，二者互不依赖。

### 第一轮：棋盘渲染与对局交互精修

#### 4.1.1 移除棋盘表面"刮痕"

- **现象**：棋盘格线之上浮现大量细而短的线条，观感类似被硬物划伤，与"真实自然"的目标相悖。
- **根因**：`draw_board` 在绘制网格线之后，仍执行一段"木纹质感"代码——以固定随机种子 `Random(11)` 在棋盘面上绘制约 110 条、长度 0.6~2.4 格、方向随机（含斜向）的 `width=1` 浅色短线段。四个因素使其成为"刮痕"而非木纹：① 高频短促 + 方向杂乱；② 固定种子使位置一成不变，强化"永久损伤"错觉；③ 颜色与背景对比度低、若隐若现；④ 真实木纹应是连续长向纹理。
- **修复**：删除该绘制块，棋盘表面改为 16 级竖向纯净渐变（`blend(bg_a, bg_b, i/15)`），源码中以注释明确标注"木纹质感（随机短线条）已移除"。

```python
# 原代码（已删除）：
if t.get("grain"):
    rng = _rnd.Random(11)
    for _k in range(min(110, n*n//3)):
        ln = cell * rng.uniform(0.6, 2.4)
        ... c.create_line(gx, gy, ex, ey, fill=grain_col, width=1)

# 现仅保留纯净渐变：
for i in range(16):
    col = blend(t["bg_a"], t["bg_b"], i/15)
    c.create_rectangle(x0, yy0, x1, yy1, fill=col, ...)
```

#### 4.1.2 消除棋子周围"正方形阴影光环"

- **根因**：`stonefx.render_stone` 中，投影先高斯模糊，再裁切在正方形图像边界内。原 `pad` 留白不足（约 `max(3*S, R*0.36)`），模糊后的投影被图片矩形边界截断，大棋子周围就显出方形光环。
- **修复**：留白改为完整容纳模糊后投影，并收紧投影使其贴合棋底。

```python
# 修复后（stonefx.py）
blur_env = R * 0.22           # 环境投影：柔和但克制
blur_con = R * 0.12           # 接触投影：贴合棋底、清晰
shadow_extent = R*1.04 + R*0.14 + 3*max(blur_env, blur_con)
pad = int(round(shadow_extent + 6*S))

base = _over(base, _tint(ell, "#000000", alpha=64,  blur=blur_env))  # 环境
base = _over(base, _tint(ell, "#000000", alpha=150, blur=blur_con))  # 接触
```

- **效果**：方形光环消失，改为贴合棋底的柔和接触式阴影，立体感更真实。

#### 4.1.3 落子音效替换为清脆"嗒嗒嗒"

`_gen_stone` 重写为三连击脆响：每声"嗒" = 高频脆响 + 低 body + 极短噪声瞬态，快速衰减；三声间距紧凑、音量递减、音高微扬。重新生成 `assets/sounds/stone.wav`（约 255ms）作为默认落子音。

```python
def _gen_stone():
    def _click(freq, dur, vol):
        env   = math.exp(-t*70.0)                      # 快衰减 → 脆
        tok   = sin(2*pi*freq*t)                       # 材质环（清脆）
        thock = sin(2*pi*(freq*0.42)*t)*0.35           # 低 body
        noise = (rng.random()*2-1)*exp(-t*220.0)*0.5   # 撞击瞬态
    clicks = [_click(2500,0.045,1.00), _click(2700,0.040,0.82), _click(2350,0.045,0.68)]
```

### 第二轮：音效素材 / 图标 / 滚动优化

#### 4.2.1 落子音效替换为用户提供的 MP3

- **关键隐患**：原 `SoundManager` 仅识别 `.wav`，且 `set_volume` 会重写全部 WAV。若直接覆盖为 MP3，程序既播不了，也会在调音量时被合成音覆盖。
- **修复**：
  1. 用户 MP3 复制为 `assets/sounds/stone.mp3`；新增 `_CUSTOM_FILES = {"stone": "stone.mp3"}` 机制——存在即接管该音效，`_ensure_files` / `set_volume` 跳过它；
  2. `_play_task` 按扩展名选 MCI 设备：`.mp3` → `mpegvideo`（Windows 内置解码器）、`.wav` → `waveaudio`；MP3 音量经 `setaudio ... volume to N`（0~1000）实时施加；
  3. 采用常驻 alias + `seek`/`play`，避免每次 `close` 重开；并区分 MP3 轨（异步）与 WAV 轨（同步阻塞）双队列，**消除"落子音延迟"**。
- **验证**：MCI 实测 `open`/`play` 该 MP3 全部返回 0、时长 319ms；`SoundManager` 映射与入队正常；打包配置 `六子棋.spec` 含整个 `assets/sounds` 目录，MP3 自动入包。

#### 4.2.2 修正"上一首 / 下一首"图标方向

- **根因**：`buttonfx._draw_icon` 中 ⏮ 的三角尖朝右、⏭ 的三角尖朝左，方向恰好画反。
- **修复**：按标准媒体图标重绘——⏮ 竖杠在左、三角尖朝左；⏭ 竖杠在右、三角尖朝右；比例微调，仍为 4× 超采样矢量绘制。

#### 4.2.3 修复歌单按钮字体 / 乱码问题

- **根因**：按钮文字经 PIL 渲染，而 **PIL 不做字体回退**——原标签含 U+266A（♪）音符，雅黑 / 艺术字体缺该字形，渲染成方框乱码。
- **修复**：
  1. 歌单按钮文字改为纯"歌单"二字（去 ♪），在艺术字体下清晰且风格统一；
  2. 同时把 ♪ 纳入 `_ICON_GLYPHS` 并实现矢量八分音符（音符头 + 符干 + 右扬符尾）作为通用兜底——今后任何 ♪ 用法都不会再出方框。

#### 4.2.4 侧栏稳定性与滚动流畅度

- **晃动根因**：`_side_update_scroll` 挂在 `Configure` 事件上且内部调用 `update_idletasks()`，造成重入式重排；对局中每秒的状态 / 计时 / 曲名刷新都会触发抖动，`scrollregion` 又无差别重设。
  **修复**：变化检测（值未变不重设）+ 彻底移除 `update_idletasks`——侧栏现在静止不动。
- **卡顿根因**：原滚轮按 "unit" 滚动，一格 ≈ 窗口高 1/10 的大跳变，观感"一卡一卡"。
  **修复**：改为像素级动画滚动——滚动量累加进动画队列，每 12ms 推进 ≤36px（约 3000px/s 上限），快速连滚自然累加、不丢帧；并以 `bind_all` 兜底，让滚轮悬停在侧栏内按钮 / 滑杆上也能滚动（侧栏外区域放行默认行为）。

### 第三轮：PostgreSQL 一键配置脚本

### 第四轮：项目体积清理诊断

#### 4.4.1 诊断结论（近 1GB 来源）

对全工程做内容级（MD5）重复扫描：**935MB 中约 627MB 是"重复副本"**，且几乎全部位于 `dist\`。

| 目录 | 大小 | 性质 |
|---|---|---|
| `dist\`（清理前） | 627 MB | PyInstaller 打包产物（`_internal` 331MB 解释器 + assets/config 额外 xcopy 顶层拷贝 → 每文件 3 份） |
| `assets\music` | 273 MB | 6 首古筝曲 WAV，源素材各不相同，**非重复** |
| `src / config / 其他` | ≈35 MB | 源码与配置，保留 |

#### 4.4.2 重复文件根因

`dist\六子棋\_internal\`（331MB）是 PyInstaller 冻结的一整套 Python + 源码 + assets 副本；`build_exe.bat` 又用 `xcopy` 把 assets/config 再拷贝一份到 `dist\六子棋\` 顶层 → 每个文件出现 3 份，仅音乐文件重复就吃掉约 547MB。

**关键结论**：`dist\` 可安全删除——`启动六子棋.bat` 用 `venv\python run.py` 跑源码，运行游戏不依赖 `dist\`；需要分发时运行 `build_exe.bat` 可随时重建。

#### 4.4.3 清理执行与现状

- 已清除遗留临时文件 `_t.txt`（单文件，删除成功）；
- `dist\`（1650 文件）的批量删除被环境"安全删除"护栏硬性拦截（超过 50 文件需二次确认），属环境级安全控制，无法以编程方式绕过；
- 提供手动清理指引：资源管理器右键删除 `dist` 并清空回收站，或 `rmdir /s /q dist`。游戏运行与源码零影响。
