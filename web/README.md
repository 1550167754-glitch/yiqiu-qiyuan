# 弈趣棋苑 · 网页版

把桌面版（Python + Tkinter）的棋类合集改写成**纯前端网页**：同一套引擎代码用 Node 跑回归测试、用浏览器跑网页版，将来再做微信小程序只需补一层渲染适配。

## 一、跑起来

```bat
本地预览网页版.cmd          :: 启本地服务器 + 自动开浏览器（只用系统里的 node）
node web\serve.js 5180 web\dist\site   :: 预览"发布产物"目录（上线前自检用）
```

或者手动：

```bat
node web\serve.js           :: 默认 http://127.0.0.1:5178/
node web\serve.js 8080      :: 指定端口
```

## 二、当前功能

| 项目 | 状态 |
|---|---|
| 六子棋 Connect6（19×19 / 连六 / 首轮 1 子、其后每轮 1~2 子） | ✅ 完整 |
| 五子棋 Gomoku（15×15 / 连五 / 每轮 1 子） | ✅ 完整 |
| 中国象棋 Xiangqi（9×10 / 七种走法 / 马蹩腿 / 象塞眼 / 炮隔子 / 飞将 / 将死困毙） | ✅ 完整 |
| 人机对战、本地双人 | ✅ |
| 连珠类 AI 三档（Alpha-Beta + PVS + 置换表 + 迭代加深 + 威胁延伸 + TSS 冲四搜索 + 五子棋 VCF 算杀） | ✅ |
| 象棋 AI 三档（迭代加深 + Alpha-Beta + 置换表 + 杀手/历史启发 + 吃子静态搜索 + 子力位置表 + 机动性/将帅安全） | ✅ |
| 两步落子（连珠类选点→确认；象棋选子→点目标，带可走点/可吃点提示） | ✅ |
| 悔棋（人机一次撤一整轮）+ **倒退动画** | ✅ 三种棋都有 |
| 胜负判定与获胜连线高亮、最后一手标记、被将军提示 | ✅ |
| 本地存档与战绩（localStorage，结构与桌面版数据库同构） | ✅ |
| 本地音效/背景音乐、艺术字材质、皮卡鱼 NNUE | ❌ 有意省略（见下） |

**有意砍掉的**：背景音乐与音效（桌面版靠 Windows MCI，网页端要另做音频管线，且素材 272MB）、
艺术字与棋子材质预渲染（桌面版用 PIL，网页端改用 Canvas 径向渐变重画，观感接近且零依赖）、
皮卡鱼 NNUE 象棋引擎 —— 它是**原生 C++ 可执行文件 + 48.4MB 神经网络权重**，
靠 UCI 管道通信，浏览器与微信小程序**不能起子进程、不能执行本地二进制**；
就算编成 WebAssembly，48MB 权重也塞不进（小程序整包上限才 20MB）。
象棋那一档因此手写了一个纯 JS 引擎（能搜到 4~6 层，会吃子、会应将、会走杀棋）。

## 三、目录结构

```
web/
├─ index.html          页面骨架（对局 / 战绩 / 规则 三页）
├─ style.css           深色 + 木色棋盘样式（含手机端单列布局）
├─ app.js              浏览器主控制器：画布、输入、AI 调度、悔棋动画、存档
├─ serve.js            零依赖本地静态服务器（开发预览用）
├─ build.js            把 engine/*.js 打成一个浏览器单文件
├─ dist/engine.bundle.js   打包产物（浏览器用；不要手改）
├─ engine/             【平台无关】核心引擎，Node 与浏览器共用
│   ├─ board.js        棋盘、胜负判定、候选点
│   ├─ game.js         对局状态机（轮次 / 悔棋 / 棋谱）
│   ├─ ai.js           六子棋・五子棋 AI
│   ├─ boardview.js    棋盘渲染器（只认 Canvas 2D 公共接口，三端可复用）
│   ├─ xiaqi.js        中国象棋规则引擎 + 纯 JS 象棋 AI
│   └─ store.js        存档适配层（浏览器 localStorage / 小程序 wx.storage）
└─ tests/              回归测试与真实浏览器截图脚本
```

### 为什么是「零依赖」

引擎层只用 CommonJS，`build.js` 往一个 60 行的模块注册表里打包，浏览器通过全局 `E` 取用（`E.board` / `E.game` / `E.ai` / `E.boardview` / `E.xiaqi` / `E.store`）。不引入 webpack/vite，不联网装包，克隆下来 `node web/build.js` 就能用。

## 四、测试

```bat
跑网页版测试.cmd                          :: 一把跑完下面 7 项
node web\build.js                        :: 重新打包引擎（改完 engine/ 必跑）
node web\tests\run.js                    :: 连珠类引擎回归（49 项）
node web\tests\wincheck.js               :: 胜负判定穷举对拍（59 万组合）
node web\tests\xqcheck.js                :: 象棋攻击检测对拍（8 项）
node web\tests\xqstrength.js             :: 象棋棋力抽检（7 项）
node web\tests\apptest.js                :: 假 DOM 真跑 app.js（32 项交互链路）
python web\tests\parity.py               :: 跨语言对拍：桌面版(Python) vs 网页版(JS)
```

### 两个"对拍"测试是关键，值得单独说明

**`wincheck.js`**（连珠类胜负判定）：在一维线段上枚举 `3^11 = 177147` 种「空/黑/白」组合，
对每个候选落点分别用**棋盘真值**（真落子后问 `checkWin`）和**AI 的快速判定**（`isWinMove`）算一遍，
要求逐点一致。当初就是它抓出了「缺口/跳形/双侧缺口」的判定错误 —— 手写期望值发现不了，
因为写错的人会把错误认知当成正确答案。

**`parity.py`**（跨语言对拍）：用固定种子生成 80 个**完全相同的局面**（连珠类 40 + 象棋 40），
分别交给桌面版 Python 引擎与网页版 JS 引擎，逐项比对：
合法着法集合、候选点集合、`checkWin`/`scanWin`、被将军判定、棋盘网格。
**这是"移植时有没有悄悄改错规则"的唯一硬证据** —— 移植最容易出的错不是崩溃，
而是细节走样（比如象棋炮的炮架计数），小规模手测根本看不出来。

## 五、发布到公开网址（免费）

**发布产物在 `web/dist/site/`**（`node web/build.js` 自动生成，约 165 KB，自包含、无后端）。
把**这个目录**整个上传/拖拽到静态托管即可；不要传整个项目（`web/` 是开发目录，里面还有源码与测试）。

| 方式 | 步骤 | 备注 |
|---|---|---|
| **Netlify Drop**（最省事） | 打开 <https://app.netlify.com/drop>，把 `web/dist/site` 拖进去 | 免注册即可拿到 `https://xxx.netlify.app`；要保留站点再注册 |
| **Cloudflare Pages / Vercel** | 注册后新建项目，上传同一目录 | 免费额度足够；国内访问一般比 GitHub Pages 稳 |
| **GitHub Pages** | 推仓库 → Settings → Pages 选分支与目录 | ⚠ **国内网络下 github.com 常被墙**（本机实测 `github.com` 与 `raw.githubusercontent.com` 超时，只有 `api.github.com` 偶尔通），放在最后考虑 |
| **Gitee Pages** | 推 Gitee → 服务 → Gitee Pages | 国内快；需实名认证，且开通入口时有调整，以官网为准 |
| **微信里打开** | 直接把网址发聊天/朋友圈 | 微信内置浏览器能正常打开，**不需要小程序账号、不需要备案、不需要服务器** |

> 想再进微信小程序：`engine/` 这层可原样复用（不碰 DOM、也不碰 `wx`），
> 只要写一个小程序 Canvas 2D 适配层（把 `boardview.js` / `xqview.js` 需要的 ctx 方法
> 与触摸坐标对上），再把 `store.js` 的后端换成 `wx.setStorageSync` 即可。
> 这也是当初把引擎与渲染拆开的原因。

## 六、已知限制

- **AI 是同步搜索**，浏览器单线程。点确认后会先渲染"AI 思考中"再开始计算
  （避免看起来像卡死），耗时上限：连珠类 0.25/1.2/2.6 秒，象棋 0.35/1.4/3.2 秒。
  要在思考期间保持界面完全流畅，需把搜索搬进 Web Worker（引擎已支持 `stop()`，接口现成）。
- 五子棋的 **VCT**（连续活三算杀）未移植，只做了 VCF（连续冲四）；六子棋本来就不走 VCF/VCT。
  象棋的 VCT 同理未做。
- 象棋 AI 是纯 JS 手写引擎（搜 4~6 层），**不是**皮卡鱼那个强度；对休闲与中级玩家够用。
- 战绩只存本机浏览器；换浏览器/清缓存就没了。
- 未做音效与背景音乐。
